# 竞赛论文内容深度与篇幅门禁

本文说明 Beacon 如何避免“PDF 编译成功但模型、算法或论证仍有硬伤”，以及如何复现绿色物流历史参考稿。
它描述现行代码契约；历史方案仍保存在 `docs/superpowers/`，不得用来判断当前行为。

## 1. 验收目标

论文必须同时满足内容证据和版式篇幅要求：

- 主方案真实读取声明的附件，并通过 RESULT 数值合理性、有限车队和服务覆盖检查；
- 至少存在两个独立执行且口径一致的基线；
- 敏感性中心点复现正式主方案，不混入旧 attempt；
- 城市绿色物流主方案必须输出算法搜索、随机稳健性、服务诊断和五类动态事件证据；
- 最终模型评审至少 8 分，模型—代码一致性至少 8 分，论文评审至少 9 分；
- 综合评分至少 8 分，各维度至少 7 分，其中结果正确性至少 8 分；
- PDF 在真正的附录首页前至少有 12 个非空正文页、10000 个非空白字符；
- LaTeX 两遍编译成功，且逐页渲染后无乱码、裁切、重叠或严重溢出。

默认质量阈值由以下环境变量控制：

```dotenv
MATH_AGENT_MIN_MODEL_CRITIC_SCORE=8
MATH_AGENT_MIN_MODEL_CODE_SCORE=8
MATH_AGENT_MIN_PAPER_CRITIC_SCORE=9
MATH_AGENT_MIN_FINAL_SCORE=8.0
MATH_AGENT_MIN_EVALUATION_DIMENSION=7.0
MATH_AGENT_MIN_RESULT_CORRECTNESS=8.0
MATH_AGENT_MIN_PAPER_BODY_PAGES=12
MATH_AGENT_MIN_PAPER_BODY_CHARS=10000
```

页数和字符数只判断“是否完整”，不奖励冗长。降低篇幅下限是为了取消“写满 20 页即可”的错误激励；
模型覆盖、算法实现、结果证据和论证深度由更严格的上游评分门禁负责。

目录中的“附录”条目不算附录首页。正文起点和附录起点都按页面首个非空标题识别，避免目录误判。

## 2. 证据生成链

绿色物流安全求解器在一次正式主方案执行中完成以下工作：

1. 从订单、距离矩阵、时间窗和客户坐标四个附件构造有限异构车队方案；
2. 正式主解至少执行一种跨路线改进算子；确定性安全求解器保留路线内 2-opt 作为可行性兜底，
   并记录初末目标、改善量、移动次数和运行时间；
3. 固定正式路线，用题面速度分布生成 200 个可复现交通情景；
4. 在每个情景中重算等待、晚到、燃油或电耗、返程能耗和碳成本；
5. 统计晚到任务、尾部晚到、载重/容积利用率和空载返程比例；
6. 独立构造订单取消、新增订单、地址变更、时间窗收紧和车辆故障事件；
7. 输出结构化证据行，供 writer、evaluation 和 finalizer 共用。

四类深度证据标签为：

```text
ALGORITHM_SEARCH
ROBUSTNESS
SERVICE_DIAGNOSTICS
DYNAMIC_EVENTS
```

门禁不仅检查标签存在，还检查必需字段、概率范围、非负性和交叉一致性。例如算法改善量必须等于
初末目标之差，五类事件成功率必须与总体回退率一致。缺字段、非法概率或自相矛盾的输出不能进入论文。

## 3. 动态事件口径

- 订单取消：从原路线移除任务后复算可行性；
- 新增订单：复制一个真实附件任务作为压力样本，同时枚举已有路线和未启用备用车辆，不虚构需求属性；
- 地址变更：保留原时间窗，只替换为附件中的另一个真实客户节点；
- 时间窗收紧：先移除旧任务，再用收紧后的时间窗唯一回插任一路线；
- 车辆故障：释放整条故障路线任务，在其余路线和未启用备用车辆中累计迁移。

地址和时间窗变更不能保留旧任务再插入一个副本。新增订单也没有“来源路线”，不得无理由排除任一
候选路线。局部恢复失败的事件计入回退率，不能从统计中删除。

## 4. 写作与 PDF 门禁

writer 默认由当前题目的模型、代码和证据生成论文，不再用城市物流固定长文覆盖模型章节。只有显式设置
`MATH_AGENT_WRITER_DETERMINISTIC=1` 时，才使用确定性稿件做离线回归。正式写作在摘要、模型求解、
敏感性、模型评价和结论中分别解释：

- 2-opt 带来的构造解改善；
- 固定路线蒙特卡洛与单因素重新决策的区别；
- 服务违约尾部和车辆资源利用情况；
- 五类动态事件的适用边界与升级策略。

远程论文评审或量化评价抛出 `LLMError` 时，只有显式设置
`MATH_AGENT_OFFLINE_REVIEW=1` 才允许进入离线证据审查。离线审查不沿用历史分数，而是重新检查
最终模型评审、模型—代码一致性、章节长度、主方案与独立基线、动态事件边界、敏感性和内部术语。
当前这套确定性审查的完整事实契约只覆盖城市绿色物流稿；其他题目不得把它当作通用评审替代品。

敏感性结果是追加历史。正文、表格、图像、论文评审和 LaTeX 必须共同使用
`sensitivity_formal_parameters` 指定参数的最新成功结果。城市绿色物流正式敏感性包含速度比例、
限行开始时刻、晚到惩罚及速度×限行时刻的完整 `3×3` 网格；无重复网格上的平方和占比只作
描述性解释，不能包装成显著性检验。

短表格转换使用无段首缩进的 `tabularx`；超过 12 行的表格使用可跨页并重复表头的 `longtable`，
长敏感性数组独立成段，避免把内容挤出页边界。finalizer 同时检查正文页数、非空页和字符量；
放大字号、增加空白页或延长代码附录都不能通过门禁。

图表不再集中放入单独的“关键图表”小节或 Markdown 附录。渲染器根据图的语义类型和章节关键词，
将数据画像、算法流程、方案对比、路线、动态事件和敏感性图插入最相关的论证段落之后；找不到明确
锚点时才在目标章节内均匀分散。LaTeX 使用章节浮动边界，并把图、图题和解释放在同一浮动体中，
避免图片漂移到别章或解释跨页脱离图片。

每幅正式图都必须给出不少于 80 个非空白字符的解释，优先按“结论—证据—含义—边界”组织，不能
只写“图中展示了结果”。图像分析节点负责生成实质解释，finalizer 对缺失或过短解释降级处理。

论文正文不得出现调度、节点、检查点、标准输出、产物、尝试次数、内部协议标签或机器方案标识等
运行时术语。写作阶段先对生成字段做清洗，论文评审和 finalizer 再对完整正文独立扫描；附录保留
可复现实验所需的代码和精确数值，但展示为学术化中文摘要，原始协议行只作为内部验证证据使用。

## 5. 参考重建

从一个已经包含题面、附件摘要、模型和评审状态的验证运行重建内容增强参考稿：

```powershell
uv run python scripts/render_content_optimized_reference.py `
  --source-state runs/your-verified-run/final_state.json `
  --data-dir runs/your-verified-run/data `
  --out runs/content-optimized-reference
```

`your-verified-run` 是调用方已有的验证运行，不随仓库提交；其中必须包含 `final_state.json` 和本次
运行实际使用的数据附件。输出目录必须为空。脚本会重新执行主方案、三个基线和敏感性扫描，复用正式数值、数据血缘和深度证据
门禁，然后生成 Markdown、TeX、PDF 与 `final_state.json`。它不会启动 supervisor 或生成新的
`completion.json`，因此是可复现参考验证，不是新的完整 CLI 闭环。

`runs/wodecesium-figure-narrative-optimized-v3-20260718` 仅保留为历史版式与证据回归样本：PDF 共
31 页，正文 25 页，主方案成本 140450.14 元，并执行了 200 个随机交通情景和 50 个动态事件情景。
该运行的综合评分只有 6.8、分析深度只有 5，终态为 `degraded`，因此不得再称为当前高质量参考稿。
新结果只有同时通过本节模型、代码一致性、论文和量化评价门禁，才能作为质量基准。

## 6. 解释边界

当前结果仍有以下边界，论文必须如实陈述：

- 确定性安全求解器的构造加 2-opt 只是启发式可行上界；正式主求解应补充跨路线邻域或小实例精确对照；
- 蒙特卡洛固定正式路线评估交通扰动，不等于随机规划或机会约束优化；
- 动态实验是独立单事件压力测试，不代表连续多事件滚动系统的长期最优性；
- 客户级诊断尚未按地理分区或服务等级聚类；
- 参考重建不能替代 paper critic、evaluation、human review 和最终 completion 校验。
