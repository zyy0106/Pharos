# WebUI 模拟复盘、漏洞与改进记录

更新时间：2026-09-03

## 1. 本次模拟的证据边界

上一轮 A 题模拟完成了 21 个节点和 42 次人工审批（每个节点一次 Supervisor 检查、唯一人类第一审和第二审），并保留多文件交接、递归 `incoming/`、stdout/stderr、哈希清单和 Excel 产物。该结果证明的是工作流编排、人工闸门、文件留存和确定性演示求解器可以协同运行。

它不能证明系统已经具备任意竞赛题目的真实自主建模能力。当前演示仍使用本地确定性模板和 `framework/a_solver.py`；真实 Agent 的持续读写、根据报错修复、独立数学复算、真实 MATLAB/COMSOL 执行和中文 LaTeX/PDF 交付仍需单独验收。

## 2. 本次发现并已修复的问题

### 2.1 Windows 原子晋级的瞬时权限错误

现象：递归交接复制完成后，临时目录移动到 `approved` 目录可能出现 `EPERM`、`EBUSY` 或 `EACCES`。

处理：保留原子重命名语义，对短暂占用增加有限次数退避重试；晋级前拒绝覆盖已经存在的目标目录；目录只读权限在移动成功后再设置。历史包和失败包不删除。

### 2.2 审核意见可以为空，导致审计记录失去判断依据

现象：旧版本允许空意见直接批准或退回。

处理：服务端拒绝空白或少于 2 个字符的审核意见；WebUI 在提交前同步提示。退回时额外保存 `revisionRequests`，包含阶段、审核关卡、类别、目标文件、严重程度、意见、人类标识和时间，并将修订请求传给真实 Agent 上下文。

### 2.3 已确认输入可以被追加或同名覆盖

现象：同一个项目上传同名文件会覆盖磁盘内容；确认后追加文件会造成已登记哈希与实际输入含义不一致。

处理：同一项目内拒绝重复相对路径；题目和数据确认后拒绝继续上传。需要改题或换数据时必须新建项目，形成新的输入哈希和运行链。

### 2.4 已结束运行仍可被控制

现象：完成或终止后仍可能调用暂停、恢复、终止接口，造成状态语义混乱。

处理：`completed`、`aborted`、`idle` 状态拒绝控制请求；终止时同时终止当前 Python 子进程句柄。

### 2.5 Python 执行没有硬期限和输出上限

现象：异常脚本可能长时间占用服务，或无限输出导致内存增长。

处理：增加 120 秒执行期限、每路 2 MiB stdout/stderr 截断上限、退出码/信号/超时字段，并在终止或超时后保留失败日志。该限制是工作流安全边界，不等同于完整的操作系统级沙箱。

### 2.6 产物读取接口的访问范围过宽

现象：原接口允许读取项目目录内任意文件，和“只读运行证据”的意图不一致。

处理：`artifact` 和 `download` 只允许访问 `runs/framework` 数据目录。项目源文件仍由上传和运行流程内部读取，但不会通过通用产物接口暴露。

### 2.7 本地服务缺少跨来源请求拒绝

现象：其他本机网页若能向 localhost 发请求，可能尝试构造状态变更或上传请求。

处理：对带 `Origin` 的请求仅接受当前 `127.0.0.1`、`localhost` 和 `[::1]` 同端口来源；其他来源返回 403。该措施不能替代身份认证，因此 WebUI 仍应只监听回环地址，不应直接暴露到局域网或公网。

### 2.8 审计事件仅在状态内保留最近 500 条

现象：SSE 状态内存只保留最近事件，长运行或多次重连时无法仅靠状态接口查看更早事件。

处理：新增 `GET /api/framework/events/history?after=<sequence>&limit=<n>`，从 `events.jsonl` 增量读取历史事件；SSE 客户端按序号去重，避免重连重复展示。事件文件仍为追加写入，未删除旧记录。

### 2.9 可见性不足

现象：平面节点卡片和机器事件名不足以表达当前方案、阶段和人类待办。

处理：状态返回为阶段和包补充稳定技术 ID、显示 ID、父包关系；前端增加蓝图树、当前主线、等待第一审/第二审标识和自然语言事件消息。当前树仍是“主线视图”，尚未实现完整的多分支 DAG 编辑器。

## 3. 仍存在的技术漏洞或能力缺口

以下项目没有被本次修复伪装成已完成：

1. **真实 Agent Runtime 尚未闭环。** 当前主要是一次性生成包；尚未提供受控的 `list_files/read_file/write_file/patch_file/run_command/read_log/compare_versions` 工具循环，也没有完整的 Agent 自主修复—重新运行—再交接机制。
2. **人工退回已结构化保存，但修改执行仍不完整。** 当前已能记录意见并创建新 attempt；真实模式还需要明确把意见映射到目标文件和修改范围，并检查新旧 diff 是否确实响应意见。
3. **Supervisor 的数学独立性不足。** 文件、哈希和基本证据门禁已有；目标函数、约束、单位、可行性、论文数字和程序输出的一致性仍需要独立复算器与 claim-evidence 映射。
4. **正式论文交付未闭环。** 演示文档不是竞赛论文；需要章节模板、数字证据引用、完整 LaTeX、中文编译、PDF 页数/字体/公式/图表渲染检查。
5. **MATLAB、COMSOL 和 `.mph` 尚未真实验证。** 未安装或未执行时只能标记“未执行”，不能由占位文件推断有效结果；`.mph` 应由 COMSOL 脚本执行并重新打开验证。
6. **数据质量检查仍弱。** 多 CSV 已能上传和合并登记，但多工作表、类型、缺失、重复、异常、单位、跨文件键和人类数据纳入确认还应加入正式门禁。
7. **执行隔离仍有限。** Python 有超时和输出上限，但没有完整的进程树、CPU/内存、文件系统和网络沙箱。真实比赛应在受限工作目录和低权限账户中运行。
8. **本地 WebUI 没有登录/身份认证。** Origin 校验只能降低跨来源风险，不能防止本机其他程序直接调用接口；若不可信用户共享电脑，应增加本地随机 bearer token，并避免把服务绑定到非回环地址。
9. **事件文件缺少完整性链。** 追加日志可追溯，但尚未对每条事件做前序哈希或签名；高审计场景应加入 `prevHash`、事件哈希和周期性封存。

## 4. 比赛前必须通过的验收顺序

```text
新小题真实模式
  → Agent 从零读题、生成代码并运行
  → 人类退回一条明确数学意见
  → Agent 修改代码/文档并产生可见 diff
  → Supervisor 独立复算关键指标
  → 人类双审并检查 stdout/stderr/哈希
  → 真实 LaTeX 编译并渲染检查
  → 再用完整 A 题和多个 CSV 做全流程压力测试
```

每个节点仍必须严格满足：

```text
Agent 生成或修改
→ Agent Supervisor
→ 唯一人类第一审
→ 唯一人类第二审
→ 哈希冻结
→ 下一 Agent 只读接收
```
